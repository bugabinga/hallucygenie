Repro: Create → Cover Song → Prepare cover lyrics returned an error in release container. Then Generate cover shows an error even though an audio file is selected. Container log shows `POST /api/music-cover/preprocess` reached server and returned `400` at `2026-05-28T23:26:45.827Z`; no later `/api/create-tool` for `generate_music_cover` appears. Current DB draft has `selectedTab:"cover"`, `cover_source_kind:"upload"`, `cover_style:"dub and step beatbox metal"`, empty `cover_feature_id`, empty `cover_lyrics`. No cover asset or cover `tool_input_history` row was created.
Cause: Generate cover is gated on hidden `cover_feature_id` and extracted lyrics, not on selected file. If preprocess fails, selected file remains visible but `cover_feature_id` stays empty, so Generate cover can only show `Prepare the cover source first 🎵`. Exact preprocess error is lost after response: `/api/music-cover/preprocess` catches validation/provider failures and returns `{ error }` with HTTP 400, but logs only request/status and does not persist sanitized preprocess failure metadata. Plausible preprocess causes still open: local file MIME rejection, file size/duration outside MiniMax docs constraints (6s–6m, ≤50MB), provider `base_resp` rejection, or upload/request shape mismatch.
Fix: Generate cover starts disabled/relabelled until preprocess returns `cover_feature_id`. Source/file/URL changes clear ready state. Preprocess failures keep exact user error visible in cover status and toast. Server logs sanitized preprocess validation/provider failures with source kind, MIME, size, and truncated error. Upload max now matches 50MB docs; MIME errors name MP3/M4A/MP4/WAV. Cross-ref HG-ISSUE-092, HG-ISSUE-118, HG-ISSUE-078, HG-ISSUE-117, HG-ISSUE-123.
