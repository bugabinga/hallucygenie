Repro: open Create → Image, click `Roll surprise code 🎲`. Seed becomes hidden persisted draft state and status shows `Surprise code: N`. No UI action clears it back to omitted/random-provider seed. Generate images after seed is set; some failures may be normal MiniMax failures, or may be bad seed payload.
Cause: seed UI has roll-only affordance. Hidden `#img-seed` persists through Create draft/history/tweak flow. MiniMax docs say `seed` is `integer int64`, optional, and omitted means random. App randomizer emits `1..2147483647`, server accepts `0..Number.MAX_SAFE_INTEGER`, tool sends any integer unchanged. No provider-backed seed validity contract proves accepted range/error behavior.
Evidence 2026-05-29 release container: two Create → Image runs used `n=4` with persisted seeds `964066160` and `850282692`. Successful runs saved four asset rows each, but each group had identical file sizes and identical SHA256 prefixes: `96a5bd76682ddb18` for all four latest images, `1915055bee257215` for all four prior images. UI requested four distinct local `/asset/...` IDs, so this is not merely a display-only duplicate.
Evidence 2026-05-29 direct MiniMax API: `n=4` + omitted seed returned four URL hashes and four distinct byte hashes. `n=2` + omitted seed returned two distinct byte hashes. `n=4` + `seed=964066160` returned four distinct URL hashes but one identical byte hash for all four images. One `n=4` omitted-seed call failed with provider `rpc timeout`, matching release-container failures. Conclusion: fixed seed + multi-image yields duplicate image bytes at provider response; display/storage are faithfully showing duplicates.
Fix: Create → Image has a clear surprise-code button. Create → Image omits `seed` whenever count is greater than one and updates helper text so kids know multiple pictures use fresh surprise codes. Image submit stays disabled until prompt/count are valid. `generate_image` rejects `seed` + `n>1` with a retryable invalid-parameter error instead of calling MiniMax. Tool schema tells the LLM to omit seed for multi-image requests, and invalid-parameter errors pass through to model context so it can retry. Cross-ref HG-ISSUE-078, HG-ISSUE-066, HG-ISSUE-119, HG-ISSUE-124.
